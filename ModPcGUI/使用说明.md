# ES Tool

**ES Tool** —— 基于原版命令行工具（`Login.exe`）重做的图形客户端。
界面直接使用 PCL2（Plain Craft Launcher 2）的**原生控件与完整前端资源**，1:1 还原。

## 界面：PCL2 原生 UI（一比一）

窗口 850×500（与 PCL FormMain 原版一致），无边框圆角。
**控件全部来自 PCL2 程序集本体**：`MyRadioButton` / `MyIconButton` / `MyButton` /
`MyComboBox` / `MyTextBox` / `MyCard` / `MyHint` / `MyListItem`；
样式表原样取自 PCL2 的 `Application.xaml`（颜色 + 全部控件模板），
悬停变色、按下缩放、卡片展开、下拉弹层等**交互动画由 PCL2 内置动画线程执行**。

- 顶栏导航是 PCL FormMain 同款的 **MyRadioButton 单选组**（图标+文字，
  选中项白胶囊高亮，互斥逻辑与 PCL 完全一致）
- 左侧面板：PCL PageLaunchLeft 同款结构——顶部状态胶囊、头像+账号、
  账号下拉+删除、登录/添加账号、启动模式下拉、
  **54px 高亮「启动游戏」按钮（版本/服务器小字叠在按钮内）**、
  底部 35px「一键布吉岛 / 一键 EC」按钮行
- 右侧内容区按导航切换：启动设置 / 网易客户端下载 / 联机大厅 / config 编辑 / 关于
- 下载页对齐 PCL NEMC 的 `PageDownloadNemc`：下载路径 + 版本下拉 + 刷新 +
  下载/取消 + 状态 + 进度条。版本列表走 x19 `get-for-mcstudio`（同 PCL 的 ModNemc），
  安装包从 patchlist 里的包地址下载，支持 Range 分段并发、sha1/md5 校验、
  长路径解压；装完自动把游戏路径指到该版本目录

### 接入链路

1. 拉 [Meloong-Git/PCL](https://github.com/Meloong-Git/PCL) 源码，取正式版
   `Plain Craft Launcher 2.exe`（6 MB WPF 程序集，控件类是 public 的），
   **放到 `pcl\` 时改名为 `PCL.Core.dll`**：程序集内部标识不变，控件照样能用，
   但文件后缀不再是 .exe，不会被误双击直接拉起一个 PCL2 启动器。
   CLR 按文件名找程序集时找不到，`UI/Boot.cs` 的 `AssemblyResolve` 里做了映射
2. 从 exe 的 `PCL.Resources.resources` 提取内嵌依赖
   （`MeloongCore` / `MeloongCore.Wpf` / `PCLCS` / `Newtonsoft.Json` 等）到 `pcl\`
3. `PclStyles.xaml`（**完整资源字典**：颜色 + 全部控件样式/模板）已内置在
   `src/PclStyles.xaml`，取自 PCL NEMC 的 `Application.xaml`；构建时按
   `pcl\PclStyles.xaml` 拷进输出目录，运行时 `XamlReader.Parse` 合并进
   `Application.Resources`（PCL 程序集名带空格，无法走编译期合并）。
   这一份不用再手工从 exe / 源码里抽。
4. 宿主启动时补齐 PCL 原版 `Application_Startup` 的三件初始化
   （`UI/PclMainWindow.Layout.cs → EnsurePclRuntime`）：
   `MeloongCore.Main.Init("PCL")` + `MeloongCore.Wpf.Main.Init()`、
   `Logger.Instance = New PclLogger`（不初始化它，点任何图标按钮都会
   因日志器为空抛 NRE 闪退）、`ModAnimation.AniStart()`（PCL 常驻动画线程，
   不启动它所有 AaColor/AaScale 动画只注册不执行——图标不上色、悬停无动画）
5. 项目升 `net48 + UseWPF + UseWindowsForms`，WPF 前端与原来的 129 个业务类
   在同一个程序集里，按钮直接调 `AppHost` / `Term.Submit` / `Commands`

## 关于名称

项目正式名称 **ES Tool**。窗口标题、提示框、日志、错误提示全部使用这个名字。
可执行文件名仍是 `ModPcGUI.exe`（保持与现有目录/快捷方式兼容），
原版 `Login.exe` 和 ModPc 目录结构不变。

主界面只留 4 个常用功能 + 账号，其余全部 184 条命令收进「更多功能」并按类别分好。
命令行输入框从主界面拿掉了，只在「更多功能」里保留一个高级直发入口。

- 源码级嫁接：反编译原程序 129 个类，`Console.*` 全部换成走界面的通道
- 命令逻辑、协议、加密全是原程序那一份，一条功能没少
- 账号 `user\*.json`、`config.json` 完全复用，和 `Login.exe` 并存不冲突

### 1. 登录
1. 左侧下拉选账号（来自 `user\*.json`）
2. 右边「登录方式」下拉：**自动识别 / 电脑版 / 手机版**
3. 点 **登 录**

账号名下面那行小字会自动显示这个 Sauth 属于哪种格式：
- `电脑版 Sauth（JSON）` —— `{...}` 开头
- `手机版 Sauth（ey…）` —— `ey` 开头
- `4399 账号` —— `SDK4399` 开头

「自动识别」就是按上面这个规则判；如果判错了（比如你的电脑版 cookie 恰好是 ey 开头），
手动切成「电脑版」或「手机版」再登录。选过一次会记住。

登录成功后右上角变绿：`● 已连接 · 账号名`，底部显示 UID。

没账号就点 **添加账号**，粘贴 Sauth：
- 电脑版：`{...}` 开头的 JSON
- 手机版：`ey...` 开头
- 4399：`SDK4399` 开头

> **新账号第一次登录**：服务端会返回「还没有昵称」，这时会弹出一个「设置昵称」窗口
> （原程序是在控制台里让你敲）。填完点确定即可；点「随机昵称」自动生成 `NO+UID`，
> 点「先跳过」等于暂时不设，之后能用 `setname` 命令补。昵称被占用/不合规时会再弹一次。

> 只想看功能不想登录：点左下 **离线模式**。

### 2. 启动游戏（主按钮）

- **官方联机大厅**（默认单选项）→ 走原版 `start`，从官方接口拿大厅地址
- **自定义地址** → 填 `IP:端口`，走原版 `gametype`

地址框格式：
```
127.0.0.1:1000
123.148.1.102:12665
play.bjdmc.net:19132
```
也能用空格分隔：`127.0.0.1 1000`

右边的模式下拉对应 `multiplayer_game_type`：

| 选项 | 值 | 用在哪 |
|---|---|---|
| 第三方服务器 | 100 | 布吉岛 / EC / 私人服（默认） |
| 官方大厅 | 1000 | 官方联机 |
| 局域网 | 1 | 本地局域网 |

**游戏路径**框里的 `x64_mc` 目录必须对，里面要有 `Minecraft.Windows.exe`。
改完点 **保存路径**（会写回 `config.json`），下次自动带出来。

### 2.1 房间号查 IP（PC / PE 双大厅）
在「启动设置」卡片里：

1. 类型选 **大厅房间**，填房号（比如 `68526`），点 **查 IP**
2. 状态行立刻显示 **获取中…**，然后变成 **获取成功：1.95.232.85:19622** 或 **获取失败：原因**
3. 成功后地址自动填进上面的服务器地址框，直接点启动就能进

房号是 **PC 大厅和 PE 大厅两个独立命名空间**，同一个 5 位数可能同时存在于两边、房主和地图都不一样。
所以点「查 IP」时程序会**两个大厅都搜一遍**：

- 只搜到 1 个 → 直接查，不用再选
- 搜到多个 → 下方弹出候选列表，每行标注 **PC/PE 徽标、房间号、房主、地图、人数、是否密码房**，
  点那一行的「查这个」或直接点整行，就查这一间

> 地图名来自你账号能看到的联机专区列表（PC 已购 + PE 专区），
> 别人的图你没权限读元数据时会显示「未知」，不影响出 IP。

查询完会自动退房，不会占房主的座位。

### 2.2 联机大厅（新页签）

顶部导航第二个页签「联机大厅」，或在启动设置里点「联机大厅」那一行，都会切过去。

用法：

1. 选 **PC 端 / PE 端**（两边是独立大厅，房间不互通）
2. 输入地图名关键词（不知道搜什么就点下面的快捷词：生存 / 空岛 / 建筑 / 跑酷 / 资源）
3. 左边出现地图列表（含在线人数或作者），点一张
4. 右边列出这张地图的所有房间：**房号、房主昵称、人数、是否密码房**
5. 每个房间两个按钮：
   - **详情** → 弹窗显示房间完整信息 + **玩家列表**（昵称与 UID）
   - **进入** → 自动查这个房间的 IP → 填入地址框 → 切到「官方大厅 (1000)」→ 直接启动游戏

排序下拉：**热门推荐**（接口默认顺序）/ **在线人数**（按地图在线人数从高到低）。
> PC 端接口不返回地图在线人数，PC 模式下选「在线人数」会退回原顺序；PE 端才有真实数据。

进房拿完地址会自动退房，不占房主座位。

### 快捷键与命令行参数
| 键 / 参数 | 作用 |
|---|---|
| F1 | 打开「更多功能」 |
| F5 | 启动游戏 |
| `--multi` | 允许同时开多个窗口（会抢认证端口，慎用） |
| `--force` | 跳过单实例检查 |
| `--selftest` | 不开窗口跑一遍完整自检，结果写 `selftest.log` |
| `--legacy` | 回到原版命令行模式 |

### 关闭窗口 / 残留进程
原程序里有 43 个前台线程（登录保活、聊天连接、Dummy、RPC 等），
只关主窗口**进程不会退出**，会残留并占着单实例锁，导致下次启动弹
「已经有一个 ES Tool 窗口在运行了」。

现在：
- 关窗口时先释放本地认证服，再 `Environment.Exit(0)` 强制结束全部线程
- 启动时自动清理「无窗口且已运行超过 10 秒」的残留进程
- 单实例检查改成**看有没有可见窗口**：Mutex 被占但没窗口（僵尸）直接放行；
  真有窗口则提示并把那个窗口切到前台
- 端口 11451 被占会自动顺延到 11452~11460

### 自检
命令行执行 `ModPcGUI.exe --selftest`，会在同目录生成 `selftest.log`，
内容包含：初始化、账号、命令总数、认证服端口顺延、窗体构造、本地签名、
残留进程、端口占用、关键文件大小、游戏目录 mc.cfg。

## 四、技术实现

```
ModPcGUI\src\
├── ModPcGUI.csproj          net46 / x86 / WinForms
├── Term.cs                  控制台门面：Write/WriteLine/ReadLine/Clear/颜色/标题
├── Commands.g.cs            自动生成的 184 条命令目录
├── UI\
│   ├── Boot.cs              入口（--legacy / --selftest / --demo / --features）
│   ├── MainForm.cs          启动器主界面
│   ├── FeaturesForm.cs      更多功能（命令树 + 参数表单 + 高级输入）
│   ├── LogView.cs           带缓冲队列的日志控件（后台线程安全）
│   ├── ParamDialog.cs       通用参数对话框
│   ├── AddAccountDialog.cs  账号导入
│   ├── ConfigDialog.cs      config.json 编辑
│   └── AppHost.cs           登录/离线/初始化流程封装
└── (原程序 129 个源文件，Console.* 已整体替换为 Term.*)
```

改造要点：
1. `ilspycmd` 反编译 `Login.exe` → 完整可编译源码（0 错误）
2. 全局 `Console.` → `Term.`，`Term` 实现同名成员，语法零改动
3. `Environment.Exit(0)`（登录失败直接退进程）→ 抛 `ModPcFatalException`，GUI 捕获
4. `app.Command()` 跑在后台线程，`Term.ReadLine()` 阻塞取 GUI 输入队列
5. 命令 + 参数顺序入队，正好对上原程序 `ReadLine` 的节奏

重新编译：
```bat
cd ModPcGUI\src
dotnet build ModPcGUI.csproj -c Release
```
产物 `bin\Release\net46\ModPcGUI.exe`。

## 五、常见问题

**Q：双击没反应 / 一闪而过？**
A：不在 ModPc 目录里。exe 必须和 `mcl.common.dll`、`config.json` 同级。

**Q：登录报「请求失败」？**
A：cookie 失效或网络问题，日志区会打原始响应。

**Q：点启动游戏没反应？**
A：先看「运行日志」有没有 `gametype` 那几行；再看游戏路径对不对；
再看 `Minecraft.Windows.exe` 是否被安全软件拦了。指令发出后一般 3~10 秒出窗口。

**Q：底部显示「⏳ 等待输入」？**
A：原程序正卡在某条命令的提问上。去「更多功能」看是哪个，或者直接用对应功能重发。

**Q：点一键布吉岛/EC 报 `HttpListenerException … 与现有注册冲突`？**
A：本地认证服端口 11451 被占用了，最常见的原因是**开了多个 ModPc 窗口**。
新版已经处理：
1. 11451 起不来会自动顺延到 11452~11460（日志会提示「改用 11452」）
